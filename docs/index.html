01 / Principles

The operating system should work for its user — not watch them.

Ziuf is being built from a controlled source-based Linux foundation rather than as a cosmetic reskin. The project keeps familiar Linux standards where they make sense, while owning its integration, package path and system direction.

01

Zero telemetry

No automatic reporting of user activity. Useful diagnostics are intended to remain local unless the user explicitly chooses to share them.

02

Independent foundation

A controlled Linux base, package architecture and system direction — while respecting and acknowledging the upstream projects Ziuf builds upon.

03

User first

The machine belongs to the person using it. Controls should be understandable, deliberate and recoverable.

04

Evidence before claims

Code alone does not complete a milestone. The relevant validation gate must pass before Ziuf claims it.

04 / Privacy
“Privacy should include forgetting what no longer needs to be remembered.”

Temporary session data is intended not to quietly accumulate after it is no longer needed. Technical crash, boot, service, kernel or hardware diagnostics may remain locally available when they are genuinely useful for troubleshooting.

Ziuf does not plan to upload those logs automatically or treat them as telemetry. Automatic session cleanup remains a design target until its implementation and validation gates pass.

05 / Desktop

Wayland-first.
Modular by design.

Ziuf Desktop is being developed as restartable components behind clear interfaces, with a compositor abstraction so one backend does not become the identity of the entire environment.
